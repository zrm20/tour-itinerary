# Validate JWT access tokens at the API boundary

The client-agnostic application API acts as an OAuth resource server and accepts short-lived, asymmetrically signed JWT access tokens following the [JWT access-token profile](https://www.rfc-editor.org/rfc/rfc9068.html). Validate the signature, configured issuer, intended audience, and expiry using the issuer's public keys, then resolve the authenticated identity to the permanent application user; organization and tour permissions come from application data. This avoids a provider call for every request while accepting that revoking a login session alone does not immediately invalidate an issued access token, which may remain valid until expiry; the specific token lifetime has not been selected.

Use `@nestjs/authentication` on the API side for bearer-token validation, endpoint protection, and resolving the application user. Configure its bearer provider with the trusted issuer, API audience, and public keys/JWKS, independently of the Better Auth implementation; token issuance remains exclusively in the identity-provider module. The API does not use this package to create browser cookie sessions or issue tokens.
